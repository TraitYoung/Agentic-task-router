## 一、仓库根目录一览

Python 服务代码集中在 **`backend/`**；仓库根保留 `frontend/`、`scripts/`、`tests/`、`docs/`、`data/` 及编排文件（`requirements.txt`、`docker-compose.yml`）。路径锚点由 `backend/repo_paths.py`（`REPO_ROOT` / `BACKEND_ROOT`）统一解析。

| 路径 | 职责 |
|------|------|
| `backend/main.py` | FastAPI 应用入口：健康检查、聊天（同步/SSE）、会话历史、导出 |
| `backend/repo_paths.py` | 仓库根与后端根路径常量 |
| `backend/core_logging.py` | 统一日志入口：stdout/stderr UTF-8 兜底与全局 logging 初始化 |
| `backend/agents/dev_pipeline/orchestrator.py` | **核心编排器**：正向工程流水线（5步，含并行）+ 逆向审查 |
| `backend/agents/dev_pipeline/step_agents.py` | 各步骤独立 Agent：discovery / sprint / implementation / delivery / merge / reverse_engineer |
| `backend/agents/workflow_pipelines.py` | 对外兼容导出层，委托到 orchestrator |
| `backend/schemas/workflows.py` | 流水线各步 Pydantic 结构化中间结果 + Cursor Prompt 生成函数 |
| `backend/schemas/protocols.py` | TaskIntent 等 Pydantic 协议 |
| `backend/schemas/trace.py` | TraceStep：全链路追踪步骤的 API 模型 |
| `backend/config/context_budget.py` | 上下文预算：用户原文截断 + 步骤间 JSON 摘要硬上限 |
| `backend/config/step_model_routing.py` | 步骤级模型路由：每步可独立配置 LLM 模型 |
| `backend/prompts/dev_pipeline_profiles.py` | 5 种项目画像关键词检测与工程关注点注入 |
| `backend/memory/session_cache.py` | Redis 会话热缓存（可选，无 Redis 时功能降级） |
| `backend/memory/project_cache.py` | 项目记忆持久化 |
| `frontend/app/page.tsx` | 主页面：聊天 UI、SSE 消费、Trace 折叠面板、会话管理 |
| `frontend/app/api/*/route.ts` | Next Route Handlers → 反向代理到 FastAPI |
| `frontend/lib/backend.ts` | 后端基址解析（默认 `http://127.0.0.1:8000`） |
| `scripts/dev_stack.ps1` | 开发环境一键管理（启动/停止/重启/状态） |
| `scripts/locustfile.py` | Locust 压测入口 |
| `tests/` | pytest 测试（`conftest.py` 注入 backend 到 sys.path） |

## 三、请求链路（浏览器 → 流水线）

1. **浏览器** → `POST /api/chat/stream`（Next.js Route Handler）
2. **Next**（`frontend/app/api/chat/stream/route.ts`）转发 `x-session-id`、`x-trace-id` 到 FastAPI
3. **`backend/main.chat_stream_api`**：
   - 根据 `mode` 参数（`spec` / `review`）选择流水线
   - `spec` → `orchestrator.run_dev_pipeline()`（5步正向工程）
   - `review` → `orchestrator.run_reverse_engineer()`（逆向审查）
   - 写入 Redis 会话缓存（可选）
   - 返回 SSE 流：meta（含 trace） → delta chunks → done

## 四、正向工程流水线（`run_dev_pipeline`）

```
用户输入
  │
  ├─[1] Discovery ── DevTaskSpec (需求发现、用户故事、验收标准)
  │
  ├─[2] Sprint ── DevOutline (模块拆分、数据流、待办、风险)
  │
  ├─[3/4] Parallel ── ThreadPoolExecutor(max_workers=2)
  │   ├─ Implementation ── DevCodeSketch (代码草案)
  │   └─ Delivery ── DevTestsChangelog (测试、DoD、CI/CD、回顾)
  │
  └─[5] Merge ── 一致性收敛汇总
```

每步耗时记录于 `trace[]`，步骤间仅传递 Pydantic JSON 摘要。

---

## 五、逆向审查流水线（`run_reverse_engineer`）

```
用户粘贴代码
  │
  ├─ Reverse Engineer ── ReverseEngineerSpec
  │   (推测目标、反向用户故事、架构问题、代码质量问题、缺失测试、改进计划)
  │
  └─ 生成可粘贴到 Cursor 的重构 Prompt
```

## 六、Pydantic 结构化输出模型

| 模型 | 步骤 | 说明 |
|------|------|------|
| `DevTaskSpec` | Discovery | 目标、约束、用户故事、验收标准、MVP Sprint 目标 |
| `DevOutline` | Sprint | 模块、数据流、风险、MVP 待办、Parking Lot、技术探针 |
| `DevCodeSketch` | Implementation | 语言标识、代码草案、实现说明 |
| `DevTestsChangelog` | Delivery | 测试用例、DoD、CI/CD 注意点、CHANGELOG、Sprint 回顾 |
| `ReverseEngineerSpec` | Review | 推测目标、用户故事、架构/质量问题、缺失测试、改进计划 |

所有模型均含 `field_validator` 做数量/长度截断，防止 LLM 输出膨胀。

## 七、上下文预算控制（`config/context_budget.py`）

- `WORKFLOW_USER_TEXT_MAX_CHARS`（默认 8000）：用户原文截断上限
- `WORKFLOW_STEP_JSON_MAX_CHARS`（默认 2500）：步骤间 JSON 摘要硬上限
- 均支持通过环境变量覆盖（`AX_WORKFLOW_USER_MAX_CHARS`、`AX_WORKFLOW_STEP_JSON_MAX_CHARS`）

## 八、项目画像自动检测（`prompts/dev_pipeline_profiles.py`）

关键词匹配识别 5 种项目类型，注入对应工程关注点：

| 画像 | 触发词示例 | 关注点 |
|------|-----------|--------|
| Web 应用 | react, vue, next, tailwind, 全栈 | 前后端分离、路由、SSR、SEO |
| 移动应用 | flutter, 小程序, ios, android | 跨平台、离线、推送、商店审核 |
| API 服务 | fastapi, graphql, 微服务, grpc | 接口契约、认证、并发、可观测性 |
| 数据流水线 | etl, spark, kafka, 数仓, 爬虫 | 数据质量、幂等性、增量策略 |
| 游戏工具 | unity, 资源管线, 热更新 | Tooling UX、批处理、CI 集成 |

## 九、步骤级模型路由（`config/step_model_routing.py`）

每个流水线步骤可独立配置 LLM 模型：

| 步骤 | 环境变量 |
|------|---------|
| Discovery | `LLM_DISCOVERY_MODEL` |
| Sprint Design | `LLM_SPRINT_MODEL` |
| Implementation | `LLM_IMPLEMENTATION_MODEL` |
| Delivery | `LLM_DELIVERY_MODEL` |
| Merge | `LLM_MERGE_MODEL` |

未配置时回退到 `LLM_MODEL`（兼容 `AX_LLM_DEFAULT_MODEL` / `QWEN_MODEL`）→ 默认 `kimi-k2.6`。实例按 `(model, base_url)` 缓存，见 `config/llm_settings.py`。

## 十、HTTP API 摘要

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/health` | 健康探活，附带 Redis 状态 |
| POST | `/api/v1/chat` | 非流式对话（`mode`: spec / review） |
| POST | `/api/v1/chat/stream` | SSE 流式输出（推荐），meta + delta + done |
| GET | `/api/v1/chat/history` | 会话历史（需 `x-session-id`） |
| POST | `/api/v1/chat/export` | 导出会话为 JSONL |

**SSE 事件格式：**
1. `data: {"session_id":..., "intent":..., "trace_id":..., "trace":[...], "mode":...}` — 元信息
2. `data: {"type":"delta","content":"..."}` × N — 内容块（12 字符/块）
3. `data: {"type":"done"}` — 结束

## 十一、技术栈

| 类别 | 技术 |
|------|------|
| API | FastAPI、Uvicorn、`StreamingResponse`（SSE） |
| LLM | Moonshot Kimi（OpenAI 兼容，`LLM_*` 环境变量） |
| 编排 | LangChain `ChatOpenAI`、`ThreadPoolExecutor` |
| 协议 | Pydantic v2、`with_structured_output` |
| 存储 | Redis（会话缓存，可选降级） |
| 前端 | Next.js 16、Tailwind CSS v4、TypeScript |
| 观测 | 响应/SSE 内嵌 `trace_id` + `trace[]` |

---

## 十二、设计取舍

1. **结构化输出优先**：Pydantic + field_validator 约束 LLM 输出，避免协议漂移与下游解析错误
2. **伪流式 SSE**：先生成完整回复再分块推送，实现简单，后续可升级为真 token 级流式
3. **并行阶段 2**：实现草案与测试交付通过 ThreadPoolExecutor 并行执行，降低端到端延迟
4. **JSON 摘要传递**：步骤间只传 Pydantic model_dump() 而非完整对话历史，控制 Token 成本
5. **项目画像而非微调**：关键词检测注入工程关注点，无需为每种项目类型微调模型
6. **Redis 可选降级**：无 Redis 时核心功能正常，仅丢失会话持久化
